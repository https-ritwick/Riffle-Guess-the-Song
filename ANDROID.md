# Riffle on Google Play

The Android app is a **Trusted Web Activity (TWA)**. It is a thin Android shell that opens
`https://riffle.musicquiz.workers.dev` full-screen in the user's Chrome, with no URL bar. All
game code stays the website, so **every `npm run deploy` updates the app immediately**. You only
ship a new `.aab` when the Android shell changes (icon, name, colours, package settings, a new
target SDK).

Why a TWA and not Capacitor or a WebView? Riffle runs in real Chrome, so the things that break
in WebViews keep working: Google sign-in (Google blocks OAuth in embedded WebViews), Spotify
login, `getUserMedia` microphone for voice chat, WebRTC, audio autoplay after a tap, and
WebSockets. Chrome asks for the microphone itself, so the app declares no Android permissions
beyond `INTERNET`.

```
android/
├── app/build.gradle.kts        ← package id, host, colours, version, signing (edit here)
├── app/src/main/AndroidManifest.xml
├── app/src/main/res/           ← launcher icons + splash (generated by scripts/build-og.mjs)
├── store/                      ← Play listing graphics (icon-512.png, feature-graphic.png)
├── gradlew / gradlew.bat       ← Gradle 8.14.3 wrapper (AGP 8.13, compile/target SDK 36)
└── keystore/  keystore.properties  local.properties   ← git-ignored, never commit
public/.well-known/assetlinks.json  ← tells Android the site trusts the app
scripts/android.mjs             ← helper behind the npm run android:* scripts
```

## 1. Prerequisites

| Need | Notes |
| --- | --- |
| **JDK 17 or 21** | `java -version`. Android Studio's bundled JBR works too (set `JAVA_HOME`). |
| **Android SDK** | Easiest: install [Android Studio](https://developer.android.com/studio). The build needs *Android SDK Platform 36* and *Build-Tools*; Gradle downloads missing ones automatically once the SDK licences are accepted (Android Studio → SDK Manager, or `sdkmanager --licenses`). |
| **Platform-tools (`adb`)** | Only for installing on a phone. |
| **Node 20+** | Already needed for the website. |

Check everything at once:

```powershell
npm run android:doctor
```

The helper finds the SDK through `ANDROID_HOME`, `ANDROID_SDK_ROOT` or the default install
path, and writes `android/local.properties` for you. That file is git-ignored.

> **Package id: `dev.riffle.app` (confirmed).** It is set in `android/app/build.gradle.kts`
> (`Twa.applicationId`) and **can never change** once the app is on Play. It must match
> `package_name` in `public/.well-known/assetlinks.json` (`npm run android:assetlinks` reads it
> from the Gradle file for you).

## 2. Signing

Play uses two keys:

* **Upload key**: yours. You sign every `.aab` with it. It lives in `android/keystore/` and is
  git-ignored.
* **App signing key**: Google's (Play App Signing, mandatory for new apps). Google re-signs what
  users download with it. Its fingerprint is what really matters for `assetlinks.json`.

Create the upload key **once**:

```powershell
npm run android:keystore
```

`keytool` asks for a password and a name. Then fill in the passwords in
`android/keystore.properties` (created for you, git-ignored):

```properties
storeFile=keystore/riffle-upload.jks
keyAlias=upload
storePassword=…
keyPassword=…
```

You can also leave the passwords out of the file and use environment variables, for example in CI:
`RIFFLE_UPLOAD_STORE_FILE`, `RIFFLE_UPLOAD_STORE_PASSWORD`, `RIFFLE_UPLOAD_KEY_ALIAS` and
`RIFFLE_UPLOAD_KEY_PASSWORD`.

**Back up `riffle-upload.jks` and its password** (a password manager is ideal). If you lose the
upload key you can ask Google to reset it, but that takes days. Never commit it:
`.gitignore` already excludes `*.jks`, `*.keystore`, `android/keystore/` and `android/keystore.properties`.

## 3. Build

| Command | Output |
| --- | --- |
| `npm run android:bundle` | **Signed release bundle for Play**: `android/app/build/outputs/bundle/release/app-release.aab` |
| `npm run android:apk` | Signed release APK (sideloading / testing): `android/app/build/outputs/apk/release/app-release.apk` |
| `npm run android:debug` | Builds and installs a debug build on the connected phone |
| `npm run android:clean` | Wipes Gradle build output |

Release builds stop with a clear error if no upload key is configured. You can run Gradle
directly too: `cd android`, then `.\gradlew.bat bundleRelease` on Windows or `./gradlew bundleRelease` on macOS/Linux.

## 4. Test on a phone

1. On the phone: Settings → About → tap *Build number* 7× → Developer options → enable **USB
   debugging**. Plug it in and accept the prompt. `adb devices` should list it.
2. Make sure **Chrome** is installed and up to date. It provides the TWA.
3. `npm run android:debug`. The app installs and opens on the phone.

**Seeing a URL bar at the top?** That means Digital Asset Links did not verify for this
signing key. The app still works, but it isn't full-screen. For a debug build, either:

* add the debug key to `assetlinks.json` and deploy:
  `npm run android:fingerprint -- debug`, then
  `npm run android:assetlinks -- <debug SHA-256> <other SHA-256s…>`, then `npm run deploy`.
* or tell Chrome to skip verification on this phone only: in `chrome://flags`, enable
  *"Enable command line on non-rooted devices"*, then run:

  ```powershell
  adb shell "echo '_ --disable-digital-asset-link-verification-for-url=\"https://riffle.musicquiz.workers.dev\"' > /data/local/tmp/chrome-command-line"
  ```

  Then force-stop Chrome and reopen the app.

What to check on the device:

- [ ] Launch shows the splash, then Riffle full-screen with no URL bar.
- [ ] Status and navigation bars are Riffle's dark purple.
- [ ] Google sign-in: the Google page opens, then you return to Riffle signed in.
- [ ] Spotify connect works the same way.
- [ ] Voice chat: Chrome asks for microphone permission, and other players hear you.
- [ ] Song clips play after tapping start.
- [ ] A room link `https://riffle.musicquiz.workers.dev/r/ABCD` tapped in WhatsApp opens the app.
- [ ] Back button inside a game behaves sensibly. At the home screen it closes the app.
- [ ] Light theme toggle works.

## 5. Digital Asset Links (`assetlinks.json`)

`public/.well-known/assetlinks.json` is served at
`https://riffle.musicquiz.workers.dev/.well-known/assetlinks.json` as a static asset.
`wrangler.jsonc` only sends `/api/*` to the Worker first, and `public/_headers` gives the file
`Content-Type: application/json` plus a 5-minute cache. It ships with **placeholder
fingerprints**. Replace them before the production release:

1. Upload your first `.aab` to a testing track (step 6). Play then shows the keys.
2. In Play Console, open **Test and release → App integrity → App signing**. Copy the
   **SHA-256 certificate fingerprint** from *App signing key certificate*, and also from
   *Upload key certificate*. Or get the upload one with `npm run android:fingerprint`.
3. Write both into the file. The helper validates them and takes the package name from Gradle:

   ```powershell
   npm run android:assetlinks -- AA:BB:...:FF 11:22:...:99
   ```

4. Deploy the site with `npm run deploy`, then confirm:
   * open https://riffle.musicquiz.workers.dev/.well-known/assetlinks.json in a browser;
   * Google's checker:
     `https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://riffle.musicquiz.workers.dev&relation=delegate_permission/common.handle_all_urls`
   * on a phone with the Play-installed app: `adb shell pm get-app-links dev.riffle.app`
     should say `verified`.

Keep the Play **app signing** fingerprint in the file forever. Remove the debug fingerprint
once you're done testing. If you ever move Riffle to a custom domain, change `Twa.hostName` in
`android/app/build.gradle.kts`, serve `assetlinks.json` on the new domain, and ship an app update.

## 6. Play Console checklist

Create the app in [Play Console](https://play.google.com/console): **App** = Riffle, **Game**,
**Free**. Then:

**Before your first upload**
- [x] Package id confirmed: `dev.riffle.app` (§1).
- [ ] `npm run android:bundle` succeeded with your upload key.

**Testing**
- [ ] Upload `app-release.aab` to **Internal testing** first. Add yourself as a tester and
      install from the Play link.
- [ ] Put the Play signing fingerprint into `assetlinks.json` and deploy (§5).
- [ ] *Personal* developer accounts created after Nov 2023 must run a **closed test with at least 12
      testers for 14 days** before production access is granted. Plan for it.

**Store listing** (Grow users → Store presence → Main store listing)
- [ ] App name `Riffle`. Short description, up to 80 characters, e.g. "Name the song before your friends do. Free
      guess-the-song party game." Full description from the home page copy.
- [ ] App icon: `android/store/icon-512.png` (512×512).
- [ ] Feature graphic: `android/store/feature-graphic.png` (1024×500).
- [ ] Phone screenshots: 2 to 8 at 1080×1920. `npm run screenshots` makes the home ones in
      `public/screenshots/`, but in-game shots sell better: a round in progress, the results
      podium, a Blend lobby, the daily challenge. Add 7"/10" tablet screenshots if you want
      tablet visibility. `home-wide.png` is a starting point.
- [ ] Category **Games → Music** (or Trivia). Tags: party, music, trivia.
- [ ] Contact email: the address on the site's footer. Website: the production URL.

**App content** (Policy → App content)
- [ ] **Privacy policy URL**: `https://riffle.musicquiz.workers.dev/privacy`
- [ ] **Account deletion**: Google sign-in creates accounts, so Play requires an in-app way to
      start deletion and a web link. In the app: account menu → **Delete account** (typed
      confirmation; erases the account immediately and signs out everywhere). Web link to enter
      here: `https://riffle.musicquiz.workers.dev/delete-account` (in-app steps, email fallback,
      what is deleted vs kept and for how long).
- [ ] **Ads**: No ads.
- [ ] **App access**: everything works as a guest. Mention that groups need Google sign-in, and
      give reviewers a test Google account if you want them to see groups.
- [ ] **Target audience**: 13+ (or match the minimum age in `/terms`). Don't target children, or the
      Families policy applies.
- [ ] **Content rating** (IARC questionnaire): no violence or gambling. **Users can interact**
      (yes: text chat, voice chat, custom names, player-made quizzes). **Shares location**
      (no: only approximate city for analytics, never shown to others). Song previews may
      contain explicit lyrics, so answer the music/language questions honestly. Expect around Teen / PEGI 12.
- [ ] **Data safety**. Declare what the *website* collects, because the TWA shows it. Based on `/privacy`:

  | Data type | Collected | Shared | Purpose | Notes |
  | --- | --- | --- | --- | --- |
  | Personal info → Name, Email address, User IDs | Yes (optional, Google sign-in) | No | Account management, App functionality | Name and photo are visible to roommates and group members as part of using the app, which isn't "sharing" in Play's sense. |
  | Personal info → Other (age range, gender) | Yes (optional) | No | Analytics, Personalisation | Asked once after sign-in. |
  | Photos → profile photo URL | Yes (optional) | No | App functionality | From Google. |
  | Location → Approximate | Yes | No | Analytics | Country/region/city from Cloudflare. No IP stored. |
  | Messages → Other in-app messages | Yes | No | App functionality | Room chat, deleted ~6 h after the room ends. |
  | Audio → Voice or sound recordings | Yes, **processed ephemerally** | No | App functionality | Live voice chat between players. Not recorded or stored. |
  | App activity → App interactions, Other user-generated content | Yes | No | Analytics, App functionality | Page views, feature taps, quizzes, groups, game history. |
  | Device or other IDs / Device info | Device type, OS and browser only | No | Analytics | No advertising ID. |
  | Spotify (Music → "Other" / App activity) | Yes (optional) | No | Personalisation | Top and saved tracks for Blend. Scopes `user-top-read user-library-read`. Kept until disconnect. |

  Also: **encrypted in transit** (yes, HTTPS/WSS). **Users can request deletion** (yes, with the
  deletion URL above). **Data collection required?** Optional, since guests can play. Re-check
  the table whenever `/privacy` changes.
- [ ] **Spotify**: Spotify apps in *Development mode* only allow 25 allow-listed users. Request an
      extension or quota from Spotify before launch, or Blend will fail for most Play users. The
      Spotify redirect URI stays the website's, and nothing Android-specific is needed.
- [ ] **Google OAuth**: the OAuth consent screen must be **in production** (not "Testing"). Keep the
      existing web client and redirect URI. The TWA uses the same web flow.
- [ ] **Government apps / Financial features / Health**: none.

**Release**
- [ ] Production → Create release → upload the `.aab` → release notes → roll out (staged rollout
      is fine).

## 7. Releasing an update

**Website-only change (most updates).** Run `npm run deploy`. Every installed app shows it on next
launch. No Play release is needed.

**Android shell change** (icon, splash, colours, name, target SDK bump, `androidbrowserhelper`
upgrade):

1. In `android/app/build.gradle.kts`, bump `appVersionCode` (+1, it must always increase) and
   `appVersionName` (e.g. `1.0.1`).
2. Icon or logo changed? Run `npm run og`, which regenerates the web icons, maskable icons, Android launcher icons,
   splash and `android/store/` graphics.
3. `npm run android:bundle`.
4. Play Console → Production (or a testing track first) → Create new release → upload the `.aab`.
5. Commit the version bump.

**Yearly target-SDK bump.** Google requires new apps and updates to target a recent Android API level, usually
moving each August. When Play Console warns you, raise `compileSdk`/`targetSdk` in
`android/app/build.gradle.kts`, update the AGP version in `android/build.gradle.kts` and the Gradle
wrapper (`.\gradlew.bat wrapper --gradle-version <x>`) if AGP needs it, then build and release.

## Troubleshooting

- **`Unable to establish loopback connection` from Gradle on Windows.** The `TEMP` path is too long
  or odd for Java's local sockets. Run with a short temp dir, for example `$env:TEMP='C:\tmp'; $env:TMP='C:\tmp'`.
- **`SDK location not found`.** Delete `android/local.properties` and rerun. The helper recreates it, or
  set `ANDROID_HOME`.
- **Licence errors when downloading SDK 36.** Run `sdkmanager --licenses`, or open Android Studio → SDK Manager once.
- **The app opens in a Custom Tab with a URL bar on a phone without Chrome.** That's the configured
  fallback (`FALLBACK_STRATEGY=customtabs`). Any TWA-capable browser (Chrome, Edge, Samsung
  Internet, Firefox) works.
